# ข้อเสนอฟีเจอร์เพิ่มเติมสำหรับ KUHU NET

เอกสารนี้รวบรวมความต้องการเพิ่มเติมจากอาจารย์และคำตอบที่ยืนยันแล้ว เพื่อใช้วางแผนออกแบบและพัฒนาต่อจากตัวเกมเวอร์ชันปัจจุบัน

## เป้าหมาย

- เพิ่มช่องทางสื่อสารระหว่างผู้เล่นระหว่างเล่นออนไลน์
- ทำให้มองออกทันทีว่าใครเป็นผู้เล่นคนไหนและอยู่ทีมใด
- ทำให้การเริ่มด่านใหม่ได้สถานการณ์โจทย์ที่สุ่มเปลี่ยน
- เพิ่มแรงกดดันและเงื่อนไขแพ้เมื่อหมดเวลา
- เชื่อมเนื้อเรื่องของแต่ละด่านเข้ากับภารกิจและโจทย์เครือข่าย

## 1. ระบบพูดคุยด้วยเสียง

### แนวทางที่เสนอ

เพิ่มไอคอนไมโครโฟนไว้ข้างปุ่มลำโพงใน HUD ผู้เล่นกดเพื่อเปิด/ปิดไมค์ได้ โดยไมค์เริ่มปิดและขอสิทธิ์เมื่อเปิดครั้งแรก ในโหมด 2v2 คลิกขวาที่ไอคอนไมค์เพื่อสลับช่องเสียงระหว่างทั้งห้องกับเฉพาะทีม

ในโหมด 2v2 ผู้เล่นเลือกได้ว่าจะคุยกับทุกคนในห้องหรือคุยเฉพาะคนในทีม ส่วน FFA คุยกับทุกคนในห้อง ระบบเสียงทำงานเฉพาะผู้เล่นในห้องหรือแมตช์เดียวกัน

สำหรับเกมออนไลน์ สามารถใช้ WebRTC ส่งเสียงระหว่างผู้เล่น และใช้ Socket.IO ที่มีอยู่แล้วเป็นช่องทางแลกเปลี่ยนข้อมูลเริ่มการเชื่อมต่อ (signaling) โดยไม่ส่งเสียงผ่านเซิร์ฟเวอร์เกมโดยตรง

### สิ่งที่ควรมี

- ปุ่มปิด/เปิดไมค์ และสถานะ mute ที่เห็นชัด
- แสดงสถานะไมค์เปิด/ปิดด้วยรูปลักษณ์ของไอคอน
- แจ้งเมื่อเบราว์เซอร์ยังไม่ได้รับสิทธิ์ไมค์ หรืออุปกรณ์เสียงใช้งานไม่ได้
- หยุดส่งเสียงเมื่อออกจากห้องหรือจบการเชื่อมต่อ
- ไมค์เริ่มปิดเมื่อเข้าห้อง และผู้เล่นเปิด/ปิดเองได้หลังอนุญาตครั้งแรก
- คลิกขวาที่ไอคอนไมค์เพื่อสลับคุยทั้งห้องหรือเฉพาะทีมในโหมด 2v2 โดยมีข้อความแจ้งช่องที่เลือก
- หน้าจอปกติแสดงเฉพาะไอคอนไมค์ ไม่แสดงแผงรายชื่อหรือแผงแชทเสียง

### เกณฑ์รับงาน

- ผู้เล่นเลือกคุยทั้งห้องหรือคุยเฉพาะทีมใน 2v2 ได้จากไอคอนไมค์
- ผู้เล่นปิดไมค์ตัวเองได้ และเห็นสถานะเปิด/ปิดจากไอคอนไมค์
- หลังอนุญาตไมค์ครั้งแรก ผู้เล่นเปลี่ยนสถานะไมค์ได้เองทุกเมื่อ
- เมื่อออกจากห้องแล้ว ไม่มีเสียงจากห้องเดิมค้างอยู่

## 2. สีชื่อหรือกรอบตัวละครในโหมดแข่งขัน

### แนวทางที่เสนอ

กำหนดสีประจำตัวให้ผู้เล่นทั้ง 4 คนใน FFA และกำหนดสีประจำทีมในโหมด 2v2 ใช้สีเดียวกันอย่างสม่ำเสมอบนตัวละคร ป้ายชื่อ และข้อมูลผู้เล่น เพื่อให้เห็นฝ่ายได้ทันที

ใน 2v2 ผู้เล่นทีมเดียวกันใช้สีหลักเดียวกัน และเพิ่มสัญลักษณ์หรือเฉดรองเพื่อแยกสมาชิกในทีม ส่วน FFA ใช้สีที่แตกต่างกันครบทุกคน สีต้องตัดกับฉากและไม่พึ่งสีเพียงอย่างเดียว ควรมีไอคอนหรือเส้นกรอบร่วมด้วยเพื่อให้อ่านง่าย

### เกณฑ์รับงาน

- สี/กรอบตรงกันบนแผนที่ แถบสถานะ และหน้าสรุปผล
- 2v2 แยกสองทีมได้ชัด และ FFA แยกผู้เล่นครบทั้ง 4 คนได้
- อ่านได้ทั้งบนฉากสว่างและฉากมืด รวมถึงผู้เล่นที่แยกสีบางคู่ได้ยาก

## 3. สุ่มโจทย์ใหม่ทุกครั้งที่เข้าด่าน

### แนวทางที่เสนอ

ทุกครั้งที่เข้าด่าน ให้สร้าง seed ใหม่สำหรับโจทย์ โดยคงหัวข้อความรู้และระดับความยากเดิม แต่เปลี่ยนข้อมูลสถานการณ์ เช่น IP, subnet, VLAN, MAC, อุปกรณ์ หรือเส้นทางตามเนื้อหาของด่าน การกลับเข้าหน้าด่านเดิมหรือเริ่มด่านนั้นซ้ำจะได้โจทย์ชุดใหม่

โจทย์ที่ผู้เล่นทุกคนต้องร่วมแก้ในรอบเดียวกันควรสร้างจากข้อมูลชุดเดียวกัน เพื่อไม่ให้ผู้เล่นเห็นคำตอบคนละชุด ส่วนการเริ่มรอบใหม่ให้สุ่มชุดข้อมูลใหม่ และควรตรวจว่าโจทย์ที่สุ่มออกมายังมีคำตอบที่ถูกต้องและสามารถเล่นจบได้

### เกณฑ์รับงาน

- ทุกครั้งที่เข้าด่านหรือเริ่มด่านเดิมซ้ำ ได้โจทย์ชุดใหม่ตาม seed ใหม่
- ผู้เล่นในแมตช์เดียวกันเห็นข้อมูลโจทย์ที่สอดคล้องกัน
- ทุกชุดข้อมูลที่สุ่มผ่านเงื่อนไขความถูกต้องและมีทางแก้
- โหมดใช้ข้อมูลตัวอย่างสำหรับสาธิตยังเลือกใช้ได้ หากจำเป็นต่อการเรียนการสอน

## 4. เวลาประจำด่านและเงื่อนไข Game Over

### แนวทางที่เสนอ

กำหนดเวลาของแต่ละด่านตามจำนวนขั้นตอน ความยาก และเวลาที่ต้องใช้สื่อสารกัน แสดงเวลาคงเหลือใน HUD และเตือนเมื่อใกล้หมดเวลา เมื่อหมดเวลาให้จบด่านเป็น Game Over จัดอันดับจากความคืบหน้าที่ทำได้ และให้เริ่มด่านเดิมใหม่เมื่อผู้เล่นทุกคนยืนยันแล้ว

เวลาและผลการหมดเวลาควรเป็นข้อมูลที่เซิร์ฟเวอร์เป็นผู้ตัดสิน เพื่อให้ผู้เล่นทุกคนเห็นผลพร้อมกันและป้องกันนาฬิกาแต่ละเครื่องคลาดเคลื่อน

### พฤติกรรมที่เสนอเมื่อหมดเวลา

1. หยุดรับคำสั่งที่เปลี่ยนผลของด่าน
2. แสดงข้อความ Game Over และสรุปสาเหตุว่าเวลาหมด
3. ในโหมดแข่งขัน จัดอันดับจากความคืบหน้าที่ทำได้ก่อนหมดเวลา
4. ให้เริ่มรอบใหม่เมื่อผู้เล่นทุกคนยืนยันแล้วเท่านั้น
5. เมื่อเริ่มใหม่ ให้สุ่มโจทย์ชุดใหม่

### เกณฑ์รับงาน

- แต่ละด่านมีเวลาเริ่มต้นและเวลาสิ้นสุดที่ชัดเจน
- ผู้เล่นทุกคนเห็นเวลาที่ตรงกัน และเกมจบเมื่อเวลาฝั่งเซิร์ฟเวอร์หมด
- หลัง Game Over ต้องได้รับการยืนยันจากผู้เล่นทุกคนก่อนเริ่มรอบใหม่
- เมื่อเริ่มรอบใหม่ ข้อมูลโจทย์ถูกสุ่มชุดใหม่
- การหมดเวลาไม่ทำให้ห้องหรือแมตช์ค้างอยู่ในสถานะเล่น

## 5. เนื้อเรื่องประจำด่านที่เชื่อมกับโจทย์

### แนวทางที่เสนอ

เขียนฉากหลังสั้น ๆ ให้แต่ละด่านอธิบายเหตุการณ์ ปัญหาที่เกิดขึ้น และบทบาทของผู้เล่น พร้อมภาพประกอบสถานการณ์ จากนั้นให้ข้อมูลในโจทย์และภารกิจเป็นส่วนหนึ่งของเหตุการณ์นั้นจริง ๆ

ตัวอย่างด่าน IP: บริษัทเปิดห้องทำงานใหม่ แต่เครื่องของพนักงานเชื่อมต่อเครือข่ายไม่ได้ ผู้เล่นได้รับแผนผังเครือข่ายและช่วง IP ที่องค์กรกำหนด แล้วต้องตั้ง IP และ subnet ให้ถูกต้องเพื่อให้เครื่องกลับมาใช้งานได้

### โครงสร้างเนื้อหาต่อด่าน

- **ฉาก/เหตุการณ์:** เกิดอะไรขึ้นและเกิดที่ใด
- **ภาพประกอบ:** ภาพฉากหรือเหตุการณ์ที่ช่วยให้เข้าใจปัญหา
- **บทบาทผู้เล่น:** ผู้เล่นรับหน้าที่อะไร เช่น ผู้ดูแลเครื่องหรือผู้ช่วยวิเคราะห์
- **อาการหรือปัญหา:** ระบบส่วนใดทำงานผิดปกติ
- **ข้อมูลประกอบ:** เอกสาร แผนผัง ค่าที่กำหนด หรือเบาะแส
- **ภารกิจ:** สิ่งที่ผู้เล่นต้องตรวจสอบ แก้ไข และยืนยัน
- **ผลลัพธ์:** อธิบายว่าเมื่อแก้ถูกแล้วส่งผลอย่างไรต่อเรื่อง

### เกณฑ์รับงาน

- ทุกด่านมีบทนำสั้น ๆ พร้อมภาพประกอบและอธิบายปัญหาได้ชัด
- ข้อมูลในโจทย์สัมพันธ์กับทักษะเครือข่ายที่ต้องการสอนในด่านนั้น
- การสุ่มข้อมูลเปลี่ยนรายละเอียดได้ โดยไม่ทำให้โครงเรื่องหรือคำตอบขัดแย้ง
- เมื่อผ่านหรือแพ้ มีข้อความปิดเหตุการณ์ที่สัมพันธ์กับเนื้อเรื่อง

## ลำดับความยากง่ายที่เสนอ

| ลำดับ | ฟีเจอร์ | ความยาก | สถานะ/เหตุผล |
|---|---|---|---|
| 1 | สีและชื่อตัวละครในโหมดแข่งขัน | ง่าย | ทำเสร็จแล้ว: เลือกสีได้ใน Lobby, FFA สีไม่ซ้ำ, 2v2 ใช้สีเดียวกันทั้งทีม และแสดงสีในฉาก แถบความคืบหน้า และผลการแข่งขัน |
| 2 | สุ่มโจทย์ใหม่เมื่อเข้าด่าน | ง่าย | ทำแล้ว: โหมดสุ่มตรวจว่าโจทย์ที่สร้างต่างจากครั้งก่อนของด่านเดียวกันในห้อง; ถ้าซ้ำจะสุ่มใหม่ โหมดข้อมูลตัวอย่างยังใช้โจทย์ตัวอย่างเดิม |
| 3 | เวลา, Game Over, จัดอันดับตามความคืบหน้า และยืนยันเริ่มใหม่ | ปานกลาง | ทำแล้ว: ใช้เวลาตามด่าน, จัดอันดับจากคะแนน/ความคืบหน้าเมื่อหมดเวลา, ทุกคนยืนยันเริ่มซ้ำ และเล่นเสียง Game Over |
| 4 | เนื้อเรื่องและภาพประกอบรายด่าน | ปานกลางถึงยาก | ทำแล้ว: ฉากจอดำให้ตัวละครสองตัวพูดบรีฟแบบตัวอักษรค่อย ๆ ขึ้น ไม่เกิน 30 วินาที พร้อมเสียง TEXT.mp3; ใช้โจทย์และเฉลยเดิม |
| 5 | Voice chat พร้อมตัวเลือกทั้งห้อง/เฉพาะทีม | ยาก | ทำแล้ว: WebRTC แบบ peer-to-peer และ Socket.IO signaling; HUD เหลือไอคอนไมค์ข้างลำโพง กดเปิด/ปิดไมค์ และคลิกขวาเพื่อสลับช่องเสียงใน 2v2 โดยไม่มีแผงรายชื่อ; เซิร์ฟเวอร์กรองช่องเสียงตามทีม; ชุดทดสอบเต็มผ่าน 97/97 ก่อนการปรับ UI รอบล่าสุด (ตรวจไวยากรณ์ JS หลังปรับ UI แล้ว; ยังต้องลองไมค์จริงระหว่างอุปกรณ์/เบราว์เซอร์) |

### งานที่ทำในรอบก่อน

ทำรายการสีให้ครบตามเกณฑ์: ข้อมูลสีและชื่อแสดงบนแผนที่ แถบความคืบหน้าระหว่างแข่งขัน และหน้าสรุปผล รวมถึงให้สมาชิกทีม 2v2 ใช้สีเดียวกัน ส่วนสีของอีกทีมไม่ซ้ำกัน

### งานที่ทำในรอบนี้

ทำรายการสุ่มโจทย์: ในโหมดสุ่ม ระบบจะไม่ยอมเริ่มด่านด้วยโจทย์ชุดเดิมที่ห้องนี้เพิ่งเล่น หากสุ่มได้สถานการณ์ซ้ำ จะสร้าง seed ใหม่ก่อนเริ่ม; โหมดข้อมูลตัวอย่างยังคงใช้ชุดตัวอย่างเดิมสำหรับการสาธิต

ทำรายการเวลาและเนื้อเรื่อง: เซิร์ฟเวอร์จบด่านเมื่อเวลาประจำด่านหมดและจัดอันดับจากความคืบหน้า พร้อมให้ทุกคนยืนยันก่อนเริ่มด่านเดิมใหม่; เมื่อเข้าแต่ละด่านจะแสดงฉากจอดำที่ตัวละครสองตัวพูดบรีฟด้วยข้อความค่อย ๆ ปรากฏไม่เกิน 30 วินาที พร้อมเสียง `TEXT.mp3` โดยคงโจทย์และเฉลยเดิมไว้

ทำรายการ Voice chat: ส่งเสียงระหว่างเบราว์เซอร์ด้วย WebRTC โดยให้ Socket.IO ส่งเฉพาะ signaling; ไมค์เริ่มปิดและขอสิทธิ์เมื่อผู้เล่นกดเปิด, ปิด/เปิดได้ตลอด, เลือกทั้งห้องหรือเฉพาะทีมใน 2v2, และปิด track/peer connection เมื่อออกจากห้องหรือหลุดการเชื่อมต่อ ปรับ HUD ตามคำขอให้เหลือไอคอนไมค์ข้างปุ่มลำโพง; คลิกขวาเพื่อสลับช่องเสียง และไม่แสดงแผงรายชื่อ/สถานะพูดบนหน้าจอ

ผลทดสอบล่าสุด: `npm test` ผ่าน 97/97 เคส รวม regression test ของการควบคุมตัวละครโหมด co-op และชุดทดสอบ WebSocket ของ FFA/2v2; หลังปรับ UI ไมค์รอบล่าสุดตรวจ `node --check public/js/voice-chat.js` ผ่าน แต่ยังไม่ได้รันชุดเต็มซ้ำ การทดสอบอัตโนมัติยังไม่ได้ทดสอบไมโครโฟนจริงระหว่างอุปกรณ์หลายเครื่อง

แก้บัคการควบคุมตัวละครร่วมด้วย: โหมด co-op คงตัวละครที่ตรงกับห้อง A/B ของผู้เล่น และเซิร์ฟเวอร์ตรวจ socket ปัจจุบันก่อนรับคำสั่งเดิน เพื่อป้องกันการเชื่อมต่อเก่าควบคุมตัวละครแทน

## ข้อสรุปที่ยืนยันแล้ว

- **เสียง:** มีตัวเลือกคุยทั้งห้องหรือคุยเฉพาะทีมในโหมด 2v2
- **ไมโครโฟน:** เริ่มปิดไว้ ผู้เล่นเปิด/ปิดเองได้ทุกเมื่อหลังอนุญาตครั้งแรก
- **หมดเวลา:** จัดอันดับจากความคืบหน้าที่ทำได้
- **เริ่มใหม่:** ต้องให้ผู้เล่นทุกคนยืนยันก่อน
- **สุ่มโจทย์:** สุ่มใหม่ทุกครั้งที่เข้าด่าน
- **เนื้อเรื่อง:** มีภาพประกอบร่วมกับข้อความ

## ข้อจำกัดการทดสอบเสียง

- การทดสอบอัตโนมัติยืนยันการกรองและส่งต่อ WebRTC signaling แต่ไม่ได้เปิดไมโครโฟนหรือสร้าง media connection จริง
- การใช้ไมโครโฟนต้องเปิดเว็บผ่าน HTTPS หรือ `localhost`; เบราว์เซอร์มักไม่อนุญาตไมค์เมื่อเข้าเกมผ่าน HTTP ด้วย IP เครื่องใน LAN
- มี STUN สำหรับช่วยเชื่อมต่อโดยตรง แต่ยังไม่มี TURN relay; บางเครือข่ายที่จำกัดการเชื่อมต่อแบบ peer-to-peer อาจต้องเพิ่ม TURN server
