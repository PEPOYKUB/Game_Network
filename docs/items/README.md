# ส่งต่องานระบบไอเทมและการก่อกวน

โฟลเดอร์นี้รวมไฟล์ที่ใช้ส่งต่องานให้ผู้พัฒนาคนถัดไป

## ไฟล์ในชุดส่งต่อ

- `multiplayer-03-items-and-sabotage.md` — ข้อกำหนดงานต้นฉบับ
- `items.js` — สำเนาแกนระบบไอเทมฝั่งเซิร์ฟเวอร์ปัจจุบัน (ต้นฉบับในโปรเจกต์อยู่ที่ `server/game/items.js`)
- `implementation-notes.md` — รายละเอียดพฤติกรรมที่เลือกและสัญญาการเชื่อมต่อ
- `item-drops-preview.svg` — ภาพตัวอย่างไอคอนเก็บบนพื้น 4 แบบและ Lever ที่เป็นจุดปฏิสัมพันธ์บนฉาก
- `item-concepts.svg` — ภาพแนวคิดรวมไอเทมทั้ง 5 ชนิด

## สถานะปัจจุบัน

`items.js` เป็นแกน domain logic แยกส่วน ยังไม่ได้เชื่อมกับ Socket.IO, competitive room, client UI, แผนที่จริง หรือ engine ที่ใช้เปลี่ยนค่าคอนฟิก การแก้สำเนา `item/items.js` จะไม่เปลี่ยนโค้ดที่เกมใช้งานโดยตรง ให้ทำงานในไฟล์ต้นฉบับ `server/game/items.js` หรือคัดลอกการเปลี่ยนกลับไปยังไฟล์นั้น

## ค่าที่ตกลงไว้

- Spawn สุ่มทุก 10–20 วินาทีตลอดเกม; มีไอเทมบนฉากได้ครั้งละหนึ่งชิ้น
- ไอเทมบนฉากหมดอายุใน 15 วินาที
- Inventory สูงสุด 3 ชิ้น; ไม่จำกัดจำนวนครั้งที่ใช้ได้ในหนึ่งรอบ
- เอฟเฟกต์แบบมีเวลาอยู่ 2 วินาที
- cooldown สวิตช์/Lever สุ่ม 10–20 วินาที
- Config Glitch แจ้งเตือนแบบกดปิดได้ โดยไม่ต้องมีวิธีแก้
- Shield บล็อกหนึ่งครั้ง; Reflect สะท้อนหนึ่งครั้งโดยไม่เกิดการสะท้อนวน
- FFA ห้ามเลือกตัวเอง; 2v2 ห้ามโจมตีเพื่อนร่วมทีม; ผู้เล่นที่จบแล้วไม่เป็นเป้าหมาย
- HUD เปิดเผยเฉพาะสถานะถูกรบกวนทั่วไป ไม่เปิดเผยคำตอบหรือรายละเอียดคอนฟิกคู่แข่ง

## งานที่ผู้รับช่วงต้องทำต่อ

1. ตรวจโครงสร้างโหมดแข่งขันล่าสุด แล้วต่อ state item ต่อ match และเริ่ม/หยุด timer ตาม lifecycle ของห้อง
2. ต่อ event สำหรับ spawn, pickup, use, blocked, reflected, effect start/end, Lever และ error โดยตรวจ membership, phase, inventory, cooldown, เป้าหมาย, ระยะ และ request ID ฝั่ง server
3. เชื่อม Config Erase/Glitch เข้ากับ authoritative config state ของโหมดแข่งขัน
4. เพิ่มจุด spawn และจุด Lever ที่กำหนดไว้ในแผนที่ พร้อมตรวจระยะจากตำแหน่งผู้เล่นที่ server คำนวณ
5. ทำ UI inventory, เป้าหมายโจมตี, ปุ่มใช้ไอเทม, feedback และข้อความเตือน Glitch แบบปิดได้
6. ส่งสถานะปัจจุบันกลับเมื่อ reconnect และจำกัด broadcast ไม่ให้เปิดเผยข้อมูลลับ
7. เพิ่ม/รันทดสอบตามเกณฑ์รับงานในไฟล์ข้อกำหนดต้นฉบับ

## ข้อความพร้อมส่ง

ช่วยต่อระบบไอเทมและ sabotage ในโหมดแข่งขันจากชุดไฟล์นี้ให้ครบตามข้อกำหนด ตรวจโหมดแข่งขันและโครงสร้างทีมในโปรเจกต์ก่อนเชื่อมต่อ เพราะแกน `items.js` ยังไม่ถูกเรียกใช้จากห้องหรือ UI ปัจจุบัน ให้ server เป็นผู้ตัดสินผลทั้งหมด อย่าให้ client ระบุชนิดไอเทม ตำแหน่ง ระยะ ผลเอฟเฟกต์ หรือสถานะเป้าหมายที่เชื่อถือได้ เมื่อทำเสร็จช่วยสรุปไฟล์ที่แก้ การทดสอบ และข้อจำกัดที่เหลือ
