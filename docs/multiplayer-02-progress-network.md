# งานที่ 2: ระบบความคืบหน้าผ่าน Network

เอกสารสำหรับผู้พัฒนาคนที่ 2: ทำให้ผู้เล่นเห็นความคืบหน้าของกันและกันแบบเรียลไทม์ โดยข้อมูลมาจาก server และไม่เปิดเผยคำตอบ

## เป้าหมาย

- ส่งความคืบหน้าของผู้เล่นและทีมผ่าน Socket.IO ในการแข่งขันเดียวกัน
- รองรับทั้ง FFA 4 คนและทีม 2v2
- รักษาขอบเขตความลับของโจทย์และรองรับ reconnect

## บริบทและงานที่เกี่ยวข้อง

- Socket.IO และห้องอยู่ที่ `server/game/rooms.js`; การรันด่านอยู่ที่ `server/game/engine.js`
- ตรวจ client event handling ที่ `public/js/net.js` และหน้าเล่นที่เกี่ยวข้อง
- งานที่ 1 กำหนด `mode`, ผู้เล่น/ทีม, phase และ scope ของสถานะ
- งานที่ 3 อาจมีสถานะเอฟเฟกต์ไอเทมที่นำไปแสดงเป็นสถานะถูกรบกวน
- ตกลง schema/event ร่วมกับผู้ทำงานที่ 1 และ 3 ก่อนลงมือ เพื่อหลีกเลี่ยง event และ state ซ้ำกัน

## ข้อมูลที่เปิดเผยได้

ส่งเฉพาะ snapshot/delta ที่ client ควรเห็น:

- player ID ที่ไม่ใช่ข้อมูลลับ, ชื่อแสดงผล, team ID (ถ้ามี)
- สถานะ online/disconnected และเวลาที่อัปเดต
- ขั้น/เปอร์เซ็นต์ความคืบหน้า และจำนวนวัตถุประสงค์ที่สำเร็จ
- สถานะจบเกม และสถานะถูกรบกวนแบบทั่วไป (ถ้าอนุญาตโดยงานไอเทม)
- สรุปความคืบหน้ารวมของทีมในโหมด 2v2

ห้ามส่งเฉลย, ground truth, config ที่ซ่อน, คำสั่งที่ผู้เล่นพิมพ์ หรือข้อมูลที่ช่วยแก้โจทย์แทนได้

## Source of truth และการส่งข้อมูล

- Server คำนวณ progress จากผลคำสั่ง/สถานะด่านจริง ห้ามเชื่อค่า progress ที่ client ส่งมา
- เมื่อสถานะเปลี่ยน server broadcast snapshot หรือ delta ให้ Socket.IO room ของการแข่งขัน
- เมื่อผู้เล่นเข้า/reconnect ให้ส่ง snapshot ล่าสุดจาก server
- กำหนด throttle หรือส่งเฉพาะเมื่อเปลี่ยน เพื่อลด event ที่ไม่จำเป็น
- ตรวจว่า socket เป็นสมาชิกห้องและมีสิทธิ์ได้รับ snapshot นั้น
- FFA: progress รายคนแยกกัน; 2v2: ส่งทั้งข้อมูลรายคนและสรุปทีม โดยแชร์ state ตามกติกาของงานที่ 1

## UI

- HUD/leaderboard แสดงชื่อ สี/ทีม progress เวลาอัปเดต และสถานะเชื่อมต่อ
- FFA แสดงผู้เล่น 4 ราย; 2v2 แสดงสองทีม พร้อม progress รวมและผู้เล่นแต่ละคน
- อัปเดตโดยไม่รีเฟรชหน้า และไม่บังเทอร์มินัล/พื้นที่เล่น
- แสดงสถานะกำลัง reconnect และใช้ snapshot ล่าสุดเมื่อเชื่อมต่อกลับ
- ไม่แสดงรายละเอียดที่เป็นคำใบ้หรือเฉลยแก่คู่แข่ง

## ข้อกำหนด Network/Event

ตรวจรูปแบบ event เดิมก่อนตั้งชื่อ event ใหม่ ตัวอย่างความสามารถที่ต้องรองรับ:

- รับ progress snapshot เมื่อเข้า/reconnect
- แจ้ง progress delta/snapshot เมื่อ server state เปลี่ยน
- แจ้ง presence เปลี่ยน (online/disconnected)
- แจ้งผลจบการแข่งขัน/อันดับ

Payload ต้อง serialize ได้, มี competition/room ID สำหรับตรวจขอบเขต, มี version/updatedAt สำหรับป้องกันข้อมูลเก่าทับข้อมูลใหม่ และไม่มีข้อมูลลับจาก stage run

## เกณฑ์ยอมรับ

- progress เปลี่ยนจากการเล่นแล้ว client อื่นในห้องได้รับ update ผ่าน Socket.IO
- ข้อมูลที่เห็นคำนวณมาจาก server และ client ปลอม progress ไม่ได้
- รองรับทั้ง FFA และ 2v2 พร้อมการสรุป progress รายทีม
- reconnect ได้ snapshot ล่าสุดโดยไม่มีรายการซ้ำหรือย้อนกลับไปใช้ข้อมูลเก่า
- event จากห้องอื่นหรือ socket ที่ไม่มีสิทธิ์ถูกปฏิเสธ/ไม่ถูกส่งต่อ
- payload ที่ broadcast ไม่มีเฉลย ground truth คำสั่งส่วนตัว หรือ config ลับ
- UI แสดงผลครบและยังอ่านได้เมื่อผู้เล่นหลุดหรือกำลังเชื่อมต่อใหม่

## ขั้นตอนสำหรับผู้พัฒนา

1. ตรวจ flow การส่งผลคำสั่ง/phase ใน `rooms.js` และ `engine.js`
2. ตกลง schema ร่วมกับผู้ทำงานโหมดและไอเทม
3. สร้าง server-side progress projection ที่ตัดข้อมูลลับออก
4. ส่ง snapshot/delta ผ่าน Socket.IO และเพิ่ม reconnect snapshot
5. เพิ่ม UI leaderboard/progress สำหรับสองโหมด
6. เพิ่ม/ปรับ automated tests เรื่อง broadcast, สิทธิ์, payload ไม่มีข้อมูลลับ, reconnect และทั้งสองโหมด
