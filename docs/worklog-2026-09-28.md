## 3. ฝั่งเซิร์ฟเวอร์ (เกมเอนจิน)

เขียนใหม่ทั้งหมดใน `server/game/` แทนต้นแบบเดิมที่มี 3 ห้อง

- **12 ด่านตามเอกสาร** (`server/game/stages/s01…s12`): IP & Subnet → Network/Broadcast → Default Gateway → ARP → Rogue Device → VLAN → Routing → Static Route → DHCP/DNS → Packet Capture → ACL → Final Incident
- **เทอร์มินัลแยกห้อง** แต่ละห้องใช้ได้เฉพาะคำสั่งของอุปกรณ์ที่ตัวเองควบคุม รองรับคำสั่งตรวจสอบ (ipconfig, ping, arp -a, traceroute, nslookup, capture ฯลฯ) และคำสั่งตั้งค่า (set ip, set gateway, set vlan, add route, set dns-record, remove acl-rule, enable dhcp-scope, allow port ฯลฯ)
- **`/help <topic>`** อธิบายแนวคิดและรูปแบบคำสั่ง ไม่หักคะแนน
- **Verify Before Success** ผ่านด่านได้เมื่อระบบจำลองทำงานถูกจริง (ping สำเร็จ, nslookup แปลงชื่อได้, traceroute ถึงปลายทาง, พอร์ตเปิด) ไม่ใช่การเทียบข้อความคำตอบ
- **คำตอบ (ground truth) อยู่ที่เซิร์ฟเวอร์เท่านั้น** แต่ละห้องได้รับเฉพาะข้อมูลของห้องตัวเอง
- **สุ่มค่าใหม่ทุกครั้งที่เริ่มด่าน** (IP, MAC, VLAN, พอร์ต, ชื่ออุปกรณ์, เส้นทาง) หรือเลือกใช้ข้อมูลตัวอย่างตาม PDF ได้
- **คำใบ้ 3 ระดับ** (−5 / −10 / −15) เปิดตามลำดับ ทั้งสองห้องเห็นเหมือนกัน
- **คะแนน** 100 + โบนัสเวลา − เกินเวลา − คำใบ้ − ตั้งค่าผิด (−3/ครั้ง) + โบนัสใช้คำสั่งน้อย และแสดง Service downtime
- **Leaderboard** ของทีม (คู่ A+B) บันทึกที่ `data/leaderboard.json`
- **ด่าน 12** สร้าง Final Code จากค่าที่แก้จริง เช่น `INCIDENT-CLEAR-445-30`
- ระบบห้อง: สร้างห้องด้วยเลขสุ่ม 4 หลัก, เลือกตัวละคร, สถานะพร้อม, สลับห้อง A↔B, กลับเข้าห้องเดิมได้หลังรีเฟรช และให้คนใหม่เข้าแทนช่องที่หลุดได้
- ป้องกันพื้นฐาน: จำกัดความยาวข้อความ และจำกัดความถี่คำสั่ง (10 คำสั่ง / 2 วินาที)

## 4. ฝั่งผู้เล่น (หน้าเว็บ)

เขียนใหม่ทั้งหมดใน `public/` ตาม wireframe หน้าสุดท้ายของ PDF

1. หน้าปก (ภาพจากทีมอาร์ต + ปุ่มเคลื่อนไหว + โฟลเดอร์ HOW TO PLAY)
2. หน้าตั้งค่า: เสียงเอฟเฟกต์, เพลง BGM (สังเคราะห์ด้วย WebAudio ไม่ใช้ไฟล์เสียง), ความดัง, ช่องทางติดต่อ
3. หน้าโหลด: แถบโหลด + ตัวละครวิ่ง + ตัวอักษร LOADING แบบพิมพ์ทีละตัว
4. สร้างห้อง / ใส่เลขห้อง
5. เลือกตัวละคร (สองการ์ด ห้อง A / ห้อง B, สถานะพร้อม/ไม่พร้อม, สุ่มได้)
6. เลือกด่าน (12 ด่าน พร้อมไอคอนพิกเซล, ระดับ, คะแนนที่ทำได้) + Leaderboard
7. หน้าเล่น: ฉากพิกเซลสองห้อง (ตัวละครเดินไปที่โต๊ะเมื่อพิมพ์คำสั่ง, ไฟ System Link แดง/เขียว, แพ็กเก็ตวิ่งบนสายเมื่อผ่านด่าน), เทอร์มินัล (Tab เติมคำ, ↑↓ ประวัติ, ปุ่มคำสั่งลัด), แท็บภารกิจ / ข้อมูลในห้อง (ตาราง, แผนผังเครือข่าย) / รายงาน, แชท, คำใบ้ และหน้าสรุปคะแนนพร้อมคำอธิบายเฉลย

## 5. การทดสอบ

- **ทดสอบอัตโนมัติ** (`npm test`, ไฟล์ `test/stages.test.js`) 39 ข้อ ผ่านทั้งหมด: เล่นทุกด่านทั้งข้อมูลตัวอย่างและค่าสุ่ม 40 ชุด, ยืนยันว่ารันแค่คำสั่งตรวจสอบอย่างเดียวไม่ผ่านด่าน, ห้องที่ไม่มีสิทธิ์ใช้คำสั่งจะถูกปฏิเสธ, ด่าน 12 ต้องแก้และยืนยันครบทั้งสองจุด
- **ทดลองเล่นจริงในเบราว์เซอร์** เปิดสองแท็บเป็นห้อง A และห้อง B เล่นด่าน 1, 2, 7, 12 จนจบ

บั๊กที่เจอระหว่างทดลองเล่นและแก้แล้ว:

- การ์ดตัวละครของอีกฝ่ายแสดงคำว่า "false"
- กล่องแจ้งเตือนว่างโผล่ขอบบนหน้าปก
- พิมพ์คำสั่งเร็วระหว่างที่ผลลัพธ์ยังแสดงไม่จบ คำสั่งหายไป (แก้เป็นต่อคิว)
- หน้าสรุปคะแนนไม่ขึ้นหลังรีเฟรชกลางด่าน (ฉากพิกเซลพังก่อนหน้าจอพร้อม)
- ผู้เล่นปิดแท็บแล้วเข้าห้องเดิมไม่ได้เพราะห้อง "เต็ม" (แก้ให้คนใหม่เข้าแทนช่องที่หลุดได้)
- ป้าย IP บนแผนผังถูกไอคอนบัง
- หัวเทอร์มินัลไม่แสดงชื่ออุปกรณ์
- ไฟล์ที่ไม่มีอยู่ (เช่น favicon) ทำให้เซิร์ฟเวอร์ log error

## 6. จุดที่ต่างจากเอกสาร

- **ด่าน 12:** PDF บอกว่า ping ไปเซิร์ฟเวอร์ไฟล์ไม่ได้ แต่กฎ ACL ที่ให้มาบล็อกแค่ TCP พอร์ต 445 ตามหลักจริง ping ต้องผ่าน จึงให้ `ping` ปกติผ่าน แต่ `ping <ip> -p 445` ไม่ผ่านจนกว่าจะแก้ ACL
- **ด่าน 7 (โหมดสุ่ม):** ใช้เราเตอร์ 4 ตัวแบบมีทางแยก เพื่อไม่ให้ห้อง A แก้ได้คนเดียว (โหมดข้อมูลตัวอย่างยังเป็นเส้นตรงตาม PDF)
- **ด่าน 5:** เพิ่มคำสั่ง `connect port` ไว้เปิดพอร์ตที่ตัดผิดกลับคืน
- **ช่องทางติดต่อในหน้าตั้งค่า:** ยังไม่มีลิงก์ Facebook จริง ใส่ได้ที่ `CONTACT` ใน `public/js/main.js`

## 7. Deploy ขึ้นอินเทอร์เน็ต

1. เพิ่ม `render.yaml` (ให้ Render สร้างเซิร์ฟเวอร์อัตโนมัติ) และระบุ Node เวอร์ชัน 20 ขึ้นไปใน `package.json`
2. ทดสอบติดตั้งแบบ production (`npm ci --omit=dev`) ในโฟลเดอร์แยก เซิร์ฟเวอร์ขึ้นได้ปกติ
3. Commit `e96fdf5` แล้ว push เข้า `main` ของ `PEPOYKUB/Game_Network`
4. สร้าง Blueprint บน Render จาก repo นี้ → ได้ web service `kuhu-net`
5. ตรวจเว็บจริง: `https://kuhu-net.onrender.com/api/health` ตอบ `{"ok":true}` และทดสอบสร้างห้อง/เข้าห้องจากสองแท็บผ่านอินเทอร์เน็ตได้

## 8. สิ่งที่ควรรู้ / งานต่อไป

- **แพ็กเกจฟรีของ Render จะหลับ** เมื่อไม่มีคนเข้าประมาณ 15 นาที คนแรกต้องรอราว 1 นาที และห้องที่เปิดค้างจะหาย วันนำเสนอควรเปิดลิงก์ทิ้งไว้ก่อน
- **Leaderboard ถูกล้าง** เมื่อ deploy ใหม่หรือเซิร์ฟเวอร์หลับ ถ้าต้องการเก็บถาวร ให้อัปเกรดแพ็กเกจแล้วเพิ่ม Persistent Disk ที่ `/opt/render/project/src/data`
- **push ขึ้น `main` เมื่อไร Render deploy ใหม่ให้อัตโนมัติ**
- เลขห้องมี 4 หลัก ถ้าจะเปิดสาธารณะจริงจังควรเพิ่มรหัสผ่านห้องหรือทำเลขห้องให้ยาวขึ้น
- โฟลเดอร์เกมในเครื่อง (`D:\Projects\My_All_proj\Game_Network`) ต้องกด Pull ใน GitHub Desktop ก่อนแก้ไขต่อ
- ถ้าจะใช้ฐานข้อมูลจริง `prisma/schema.prisma` ปรับตามโมเดลในหัวข้อ 8 ของเอกสารไว้แล้ว แต่เซิร์ฟเวอร์ตอนนี้ยังเก็บข้อมูลในหน่วยความจำ
